# Agent frameworks with deterministic workflow primitives

> Research note for the Forjate "agent harness". Licences were checked against the repository `LICENSE` files or the GitHub licence badge on **2026-10-30**. Release dates were read from GitHub release pages; where the fetch tooling reported an implausible year (e.g. a "2024" tag announcing Gemini 4 / Python 3.15 support) the date is normalised to 2026 and marked **(year inferred)**.

## TL;DR

- **"Google AX" is ambiguous and resolves to three different things.** *Google ADK* (Apache-2.0, Python/Go/Java/TypeScript, graph-based workflows since 2.0, May–Aug 2026) is the serious candidate. *Genkit* (Apache-2.0, Firebase team; typed "flows", Go is production-grade) is a flow/RPC framework, not an orchestration graph. *ax-llm/ax* (Apache-2.0, independent, TypeScript-first DSPy clone with "AxFlow") is unrelated to Google.
- **Only two frameworks ship a maintained declarative workflow file that an external UI could own:** Microsoft Agent Framework's **Workflow YAML** (MIT, Python + .NET, PowerFx expressions, checkpointable in C#) and Google ADK's **Agent Config YAML** (experimental, Python/Java only, LlmAgent-centric, Gemini-only). Everything else (LangGraph, Pydantic Graph, Mastra, CrewAI Flows, ADK Go/TS graph API, Eino) is **code-first**; `langgraph.json` is a deployment manifest, not a topology.
- **Durability is best obtained below the framework, not inside it.** Official Temporal integrations exist for OpenAI Agents SDK (Python GA; TypeScript package `@temporalio/openai-agents`) and Pydantic AI (`TemporalDurability`, also DBOS/Prefect/Restate). Dapr Agents (CNCF, Apache-2.0, v1.0 GA 2026-03-23) runs every agent invocation as a Dapr Workflow natively. LangGraph / Agent Framework / Mastra / CrewAI persist checkpoints themselves (Postgres, Cosmos, SQLite) but have no engine behind them.
- **Governance-first ranking for Forjate:** Dapr Agents (CNCF) > A2A protocol (Linux Foundation / Agentic AI Foundation) > MIT/Apache single-vendor SDKs (ADK, Agent Framework, LangGraph OSS, Pydantic AI, OpenAI Agents SDK). LangGraph **Server/Platform and LangSmith are not open source** (Enterprise licence key for self-hosting) — only the library is MIT. Claude Agent SDK: Python repo is MIT, but the TypeScript package is "All rights reserved, subject to Anthropic Commercial Terms" — do not treat it as OSS.
- **Recommended layering:** Temporal (already in Forjate) or Dapr Workflows as the durable engine; a *harness-owned* YAML/JSON graph schema compiled to Temporal workflow code (Go SDK), with ADK Go or Eino node semantics borrowed where useful; LiteLLM as the single model endpoint; MCP as the only tool protocol; AG-UI (MIT, 16 event types, JSON-Patch state deltas) as the UI/execution boundary; OTel GenAI semconv (still *Development*, schema gen-ai/1.42.0) for traces.

## "Google AX" disambiguated

1. **Google ADK (Agent Development Kit)** — `google/adk-python`, `adk-go`, `adk-java`, `adk-js` (TypeScript, launched 2025-12-17). Apache-2.0, 22.1k stars (Python). ADK **2.0** (Python GA 2026-05-19, Go GA 2026-06-30, TS GA 2026-08-21) replaced the 1.x hierarchical `SequentialAgent`/`ParallelAgent`/`LoopAgent` with a **directed execution graph**: nodes (function, agent, tool, join, dynamic, parallel workers), routing conditions for chains/branches/fan-out-fan-in/loops, a unified scheduler with state persistence, native HITL pause nodes (durable across restarts, same interrupt format in Python and Go) and a **Task API** (Chat/Task/SingleTurn modes). The 1.x workflow agents still exist but are deprecated in TS and "superseded" in Py/Go. **Agent Config** (YAML, `agent_class: LlmAgent`, `sub_agents` by path) is experimental, Python/Java only, Gemini-only models, and does not yet express `LangGraphAgent`/`A2aAgent` or graph edges. Deployment: Agent Runtime on Google's Agent Platform, Cloud Run, GKE, or "any container-friendly infrastructure" (Docker/Podman); `DatabaseSessionService` supports Postgres/MySQL/SQLite with row locking — **the runtime is not cloud-locked**, only `VertexAiSessionService` and the managed runtime are. A2A is first-class (A2aAgent, Task API); MCP via `McpToolset`. Go requires a recent toolchain (README states Go 1.26+). Python v2.13.0 (2026-10-23) promoted 12 experimental features to stable.
2. **Google Genkit** — `firebase/genkit`, Apache-2.0, Firebase team. Core abstraction is a **flow**: a typed, traceable, HTTP-deployable function (`genkit.DefineFlow`, `genkit.Handler()` on `net/http`). Go and JS are production-grade (Go v1.14.0 Oct 2026: typed tool pause/resume, Postgres sessions, context compression; JS 1.43.0: `@genkit-ai/otel` with GenAI semconv). Flows are *not* a graph DSL and have no checkpointing; dotprompt gives file-based prompt definitions. MCP host/client/server plugin exists (JS mature; Go plugin present). Verdict: a model/tool/prompt layer for Go services, not an orchestrator.
3. **ax-llm/ax** — independent TypeScript DSPy implementation ("pretty much the official DSPy framework for TypeScript"), Apache-2.0. Signatures (`'review:string -> sentiment:class "..."'`), GEPA optimiser, **AxFlow** (typed chainable DAG runner with branching, loops, parallel, state projection, Mermaid export) and "AxIR", an intermediate representation used to generate Python/Java/Go/Rust/C++ libraries. No durability, essentially one maintainer; release cadence is high (25.4.7 on 2026-10-29). Not Google.

## Per-framework notes

### LangGraph (MIT library; proprietary platform)
`StateGraph` with typed reducers, conditional edges, `Send` for map-reduce, subgraphs, Functional API (`@entrypoint/@task`). Durability through checkpointers (`InMemorySaver`, `SqliteSaver`, `PostgresSaver`, prune API added in 1.2.16) keyed by `thread_id`; `interrupt()` + `Command(resume=...)` for HITL; time-travel replay. **Not** declarative: `langgraph.json` only maps graph names to Python/JS paths plus `dependencies`/`env`. LangGraph Server, Studio and LangSmith require an Enterprise licence key when self-hosted (free "Lite"/Developer tier exists but is not OSS); **Open Agent Platform was archived 2026-02-25** in favour of the hosted "Agent Builder". No Temporal integration (LangChain positions the checkpointer as the durability layer). Fit: fine as a Python library, but the UI/graph-editing story is now proprietary.

### Microsoft Agent Framework (MIT, 1.0 GA 2026-04-03)
Workflows = executors (agents or functions) + edges, executed in **supersteps**; a checkpoint is cut after every superstep and captures executor state, pending messages, pending request/response pairs and shared state. Python storage: InMemory, File, Azure Cosmos (pickle with restricted unpickler); Go: JSON file store. HITL via `RequestInfoExecutor` request/response events; resuming requires identical topology and stable executor IDs. **Declarative Workflows**: YAML (`kind: Workflow` with `trigger:` in C#; `name/inputs/actions` in Python) with actions `SetVariable`, `If`, `ConditionGroup`, `Foreach`, `GotoAction`, `InvokeAzureAgent`, `InvokeFunctionTool`, `InvokeMcpTool`, `HttpRequestAction`, `Question`, `RequestExternalInput`, `EndWorkflow`; PowerFx-like `=` expressions; the same dialect Copilot Studio / Foundry emit. Python loader: `WorkflowFactory().create_workflow_from_yaml_path()`. Limitations: Python parity gaps, `=` expressions need the `powerfx` package on Python 3.14+, no OSS visual editor. Go SDK (`microsoft/agent-framework-go`) is public preview: graph workflows, checkpointing, MCP, but no declarative agents yet. Observability: OTel built in. Fit: the most complete *declarative + checkpointed* OSS workflow dialect, but written for Azure/Foundry agents.

### OpenAI Agents SDK (MIT)
Agents, tools, **handoffs**, guardrails, sessions, tracing; no graph DSL (determinism comes from your Python/TS control flow). The official Temporal integration runs the agent loop *inside* a Workflow and every model call as an Activity; `activity_as_tool` for I/O tools, plain function tools run deterministically in the workflow, hosted MCP tools with `require_approval` map to workflow callbacks. Python GA (Temporal SDK ≥ 1.33); TypeScript via `@temporalio/openai-agents` (Runner, workflow-safe tools, MCP handles, Nexus operations). Limitations: no shell/computer tools, no `SQLiteSession` across workers, streaming experimental. Model-agnostic through Chat Completions (LiteLLM works). Fit: the cleanest published blueprint for "engine owns the loop".

### Anthropic: Claude Agent SDK, guidance and Managed Agents
`claude-agent-sdk-python` `LICENSE` is **MIT (© 2025 Anthropic PBC)**; `claude-agent-sdk-typescript` `LICENSE.md` reads "All rights reserved. Use is subject to Anthropic's Commercial Terms of Service" — **fails the hard filter**; both bundle the Claude Code CLI. Primitives are harness-like rather than graph-like: hooks (`PreToolUse`, etc.), subagents, in-process MCP servers, permission modes, session resume. *Building effective agents* (2024-12-19) defines workflows as "LLMs and tools orchestrated through predefined code paths" and names the five patterns (prompt chaining, routing, parallelisation, orchestrator-workers, evaluator-optimizer). *Effective harnesses for long-running agents* (2025-11-26) and *Harness design for long-running application development* (2026-03-24) describe file-based harnesses: initializer + coding agents, `claude-progress.txt`, JSON feature list, git commits, and a planner/generator/evaluator trio communicating through artifacts — "the harness is not orchestration code, but a set of files". **Claude Managed Agents** (public beta 2026-04-08, $0.08/session-hour on top of tokens) is a hosted runtime — useful as a competitor reference, not a component. Fit: pattern source; Python SDK is usable as a *worker* behind Temporal, TS SDK is not OSS.

### Pydantic AI (MIT)
`pydantic-graph` provides typed state machines (nodes return the next node or `End`) with step persistence; the agent itself gains durability through `TemporalDurability`, `DBOSDurability`, `PrefectDurability`, `RestateAgent`, `AWSLambdaDurability`, Airflow `AgentOperator`, `AbsurdDurability`, `PGTaskDurability` — one engine per agent, model requests and tool calls journaled and replayed. Deferred/approval-required tools give HITL. MCP and AG-UI are first-class; OTel-native. No declarative file. Fit: the most engine-agnostic Python framework; pairs naturally with Forjate's Temporal.

### Dapr Agents (Apache-2.0, CNCF)
`DurableAgent` runs each invocation as a **Dapr Workflow** (the old `Agent` class deprecated at 1.0.0-rc.1); workflows compose agents and tools with activities, timers, child workflows and external events; state in any of 28+ Dapr state stores, pub/sub for multi-agent messaging, SPIFFE identities, zero-config MCP from `MCPServer` sidecar resources, LiteLLM already a dependency. v1.0 GA announced by CNCF on 2026-03-23 (NVIDIA + community); v1.1.0 (Oct 2026, year inferred) adds versioned workflow registration. Python only; "other languages TBD". Fit: the only *foundation-governed* agent framework; requires a Dapr control plane next to (or instead of) Temporal.

### CrewAI Flows, Mastra, Agno, smolagents, AG2, SK Process — brief
CrewAI Flows (MIT) are decorator-driven event graphs with `@persist` SQLite state and `@human_feedback`; the topology lives in Python, `plot()` only renders. Mastra (Apache-2.0 + proprietary `ee/`) has the richest TS workflow DSL and storage-backed suspend/resume, Studio shows the graph but does not edit it. Agno (Apache-2.0) ships its own durable runtime "AgentOS", which couples UI and execution — the opposite of the Forjate requirement. smolagents is a 1k-line ReAct `CodeAgent`, no workflow layer. AG2 1.0 (Apache-2.0, volunteer-maintained) replaced GroupChat with a Hub/channels network; too fluid to build on. Semantic Kernel Process Framework stayed "experimental" from 2024 and is superseded by Agent Framework Workflows.

### Protocols
- **MCP** — tool protocol; every framework above supports it (Dapr Agents from sidecar, ADK `McpToolset`, Genkit host/server, Agent Framework `InvokeMcpTool` even in YAML).
- **A2A** — Apache-2.0, Linux Foundation project (joined the Agentic AI Foundation 2026-08-27); spec **1.0.0** with JSON-RPC, gRPC and HTTP+JSON bindings; SDKs in Python, Go, JS, Java, .NET, Rust. ADK, Agent Framework and Genkit speak it.
- **AG-UI** — MIT, CopilotKit; ~16 event types in six categories (lifecycle, text message, tool call, **state snapshot/delta via RFC 6902 JSON Patch**, activity, raw/custom) over SSE/WebSocket/webhooks; integrations for LangGraph, CrewAI, Agent Framework, ADK, Mastra, Pydantic AI, Agno, Claude Agent SDK, AWS Strands. This is the ready-made "UI separated from execution" boundary.
- **OTel GenAI semantic conventions** — moved to `open-telemetry/semantic-conventions-genai` (Apache-2.0); as of 2026-07 every `gen_ai.*` attribute, the `invoke_agent`/`create_agent`/`execute_tool` spans and the metrics are still **Development** status, shipping from `main` against schema gen-ai/1.42.0 with no tagged release. Adopt the attribute names, expect churn.

## Which frameworks can serialise the workflow graph to a file a UI could edit?

| Level | Framework | Notes |
|---|---|---|
| Full declarative workflow (control flow + agent/tool calls) | **Microsoft Agent Framework Workflow YAML** | Richest OSS dialect (variables, If/Foreach/Goto, MCP/HTTP/function actions, HITL `Question`, checkpointable). Azure-flavoured (`InvokeAzureAgent`), PowerFx expressions, no OSS editor. |
| Declarative agent tree, no edges | **Google ADK Agent Config** | Experimental; Python/Java only; `sub_agents` composition, no graph edges, Gemini-only. ADK 2.0 graph API itself is code. |
| Rendering / IR only | ax AxFlow (Mermaid, AxIR), CrewAI `plot()`, Mastra Studio graph view, Agent Framework visualisation, Eino Dev (visual → Go code) | Export exists; round-trip editing does not, or is unverified (AxIR, Eino import/export format). |
| Code-only | LangGraph, pydantic-graph, OpenAI Agents SDK, Dapr Agents, Genkit, Agno, smolagents | `langgraph.json` is a manifest of graph entry points, not a topology. |

Conclusion: no OSS framework gives Forjate a UI-editable graph for free. The practical path is a **harness-owned schema** (YAML/JSON, versioned, JSON-Schema validated) that an AI-assisted builder emits first, with a compiler that targets the engine. Agent Framework's YAML is the best *model* to borrow action vocabulary from (and could even be a secondary export target), and ADK 2.0's node taxonomy (function / agent / tool / join / dynamic / parallel-worker, plus HITL pause with handoff vs re-entry resume) is a good minimal node set.

## Durability integrations

- **Temporal (already in Forjate):** official and GA with OpenAI Agents SDK (Py, TS) and Pydantic AI (`TemporalDurability`); pattern in both: orchestration loop in the Workflow, model calls and I/O tools as Activities, HITL as signals/updates. Temporal also publishes a Vercel AI SDK cookbook. No official Temporal bridges for ADK, LangGraph, Agent Framework, Mastra or CrewAI — these would need a thin adapter (run the framework's single-node executor inside an Activity, keep the graph walk in the Workflow).
- **Dapr Workflows:** native in Dapr Agents; Go authoring exists (`github.com/dapr/go-sdk/workflow` v1.13.0, stable, now pointing users to `github.com/dapr/durabletask-go/workflow`). SK Process Framework also has a Dapr runtime.
- **DBOS (MIT, Postgres-only):** Pydantic AI `DBOSDurability`; Python/TS SDKs, no Go SDK found in the Python repo (unverified elsewhere).
- **Framework-internal checkpointing (no engine):** LangGraph (Postgres/SQLite), Agent Framework (File/Cosmos/JSON), Mastra (storage leases), CrewAI (`@persist`), ADK (session DB + durable HITL state), Eino (checkpoint store). These give pause/resume and replay, but retries, timers, rate limiting, visibility and multi-worker scheduling remain your problem — exactly what Temporal already solves in Forjate.

## Recommended harness layering

```
┌──────────────────────────────────────────────────────────────┐
│ UI / builder  (AI-assisted; emits harness YAML; AG-UI events) │  ← never executes anything
├──────────────────────────────────────────────────────────────┤
│ Harness schema + compiler  (YAML/JSON graph → Temporal code)  │  ← Forjate-owned, Go
├──────────────────────────────────────────────────────────────┤
│ Node runtime (framework primitives)                           │
│   Go: ADK Go 2.0 graph nodes / Eino nodes / plain funcs       │
│   Py: Pydantic AI (TemporalDurability) or OpenAI Agents SDK   │
├──────────────────────────────────────────────────────────────┤
│ Durable engine: Temporal (Go SDK) — alt. Dapr Workflows       │  ← retries, timers, signals, HITL waits
├──────────────────────────────────────────────────────────────┤
│ Tools: MCP servers      Models: LiteLLM gateway (OTel out)    │
└──────────────────────────────────────────────────────────────┘
```

1. **Engine at the bottom:** keep Temporal. Model graph nodes as Activities (or one generic `RunNode` Activity dispatched by node type), the graph walk as deterministic Workflow code generated from the schema, HITL as `WaitForSignal`/Update with timers, and parallel branches as child workflows. Dapr Workflows is the alternative if Forjate wants CNCF governance for the agent layer too (Dapr Agents), at the cost of a second control plane.
2. **Schema in the middle:** a Forjate `Workflow` CRD-style YAML (nodes, edges, conditions, HITL gates, retries, budgets) with JSON Schema; borrow the action vocabulary from Agent Framework YAML and the node taxonomy from ADK 2.0; version it like Forjate's other manifests so GitOps applies.
3. **Node runtime:** in Go, ADK Go 2.0 (Apache-2.0, graph + MCP + A2A + HITL, self-hosted Postgres sessions) or Eino (Apache-2.0, typed graph, checkpoints) are the only credible pure-Go choices; both can be driven per-node from a Temporal Activity. Python nodes, when needed, run Pydantic AI with `TemporalDurability` in a separate worker.
4. **Protocols:** MCP for tools, A2A for cross-harness delegation, AG-UI for the UI stream (state snapshot + JSON Patch deltas map directly onto Temporal Workflow queries/updates), OTel GenAI attribute names on every span, exported via LiteLLM's and Temporal's OTel support.
5. **Don't** build on LangGraph Platform/Studio (proprietary), Agno AgentOS (coupled UI/runtime), Claude Agent SDK TS (not OSS) or ax (bus factor).

## Go options, specifically

- **ADK Go 2.0** (Apache-2.0, GA 2026-06-30; v2.6.0 Oct 2026, year inferred): graph engine with function/agent/tool/join/dynamic/parallel-worker nodes, durable HITL, Task API, MCP toolset, A2A, REST launcher with auth. Needs a current Go toolchain. Strongest Go agent graph.
- **Eino** (Apache-2.0, ByteDance; 13.5k stars; Go 1.18+): Chain/Graph/Workflow with compile-time typed nodes, global state handlers, checkpoint + interrupt/resume, callback aspects; Eino Dev IDE plugin generates Go from a canvas. Second choice; single-vendor Chinese hyperscaler.
- **Microsoft Agent Framework Go** (MIT, public preview): graph workflows, JSON checkpoint store, MCP; no declarative loading yet.
- **Genkit Go** (Apache-2.0, production): flows, tools with pause/resume, Postgres sessions, MCP plugin, OTel. Model/tool layer only.
- **Temporal Go SDK** (MIT) and **Dapr `durabletask-go/workflow`** (Apache-2.0): the engines; both are the correct place for determinism, not the agent framework.
- **langchaingo** (MIT, community, maintainer call open) and **swarmgo** (MIT, 360 stars, supervisor/hierarchical/collaborative patterns): usable for LLM calls or experiments, not as harness foundations.
