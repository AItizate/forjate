# Use case: `invoice-intake`

> Supplier invoices arrive as PDF attachments in a shared mailbox. Someone reads each one, types supplier, amount, date and PO number into the ERP, and flags mismatches against the purchase order. We want this automated with a human approving anything that does not match.

Assembled by `forjate:kustomize` from `.builder/` (brief, stage plan, 10 decision records, gates). Success metric: Invoices posted to the ERP without manual typing (baseline 0%, target 80% straight-through with 0 wrong amounts).

## Run it

```bash
./scripts/ephemeral/ephemeral.sh up invoice-intake        # builds app/ into invoice-intake:dev, imports it, seed -> run -> verify
./scripts/ephemeral/ephemeral.sh validate invoice-intake  # re-run only the verify Job
python3 scripts/gates/gates.py run invoice-intake --transition 'crawl->walk'
kubectl kustomize --enable-helm k8s/overlays/usecases/invoice-intake/stages/walk | kubeconform -strict -ignore-missing-schemas -
```

## Open questions

- **ai-engineering Q1** (blocks run, pack:regulated-corp#AI-1): Which model and server serve Run? Pack AI-1 approves only claude-* and ollama/*, zero egress excludes claude-*, and the catalog's only inference component fit for Run is vllm, whose served model the allowlist does not cover, while ollama is listed only for crawl and walk. The owner of the regulated-corp pack, with the catalog's owner and the CFO for cost, decides between (a) adding an approved vllm entry to AI-1 after legal review, at about USD 200 a month for a GPU node, on a lab-maturity server, or (b) accepting ollama at Run for this batch load, which needs the catalog to list it fit for Run, or an accepted exception, and can avoid the GPU cost. Until answered, model is unset at Run and Run does not start.
- **ai-engineering Q2** (blocks walk): Where does the in-cluster model run at Walk, and what turnaround must it meet? Finance ops with tenant IT answers (business Q5, Q6, Q7). This record assumes one EU node of about 8 vCPU and 16 GiB at USD 50 a month, CPU only, a batch of about 14 invoices a working day and minutes per invoice being acceptable. If the turnaround is shorter than G-AI-5 shows, the GPU path applies and the stage goes to USD 350.
- **ai-engineering Q3** (blocks walk): Who labels the real part of the golden set, independently of the clerk who approves, and may masked real invoices be kept for regression and for how long? Finance ops names the labeller; the compliance owner (business Q1) and G-DS-1 settle the retention. Without it the Walk set stays synthetic and G-AI-6 cannot close.
- **ai-engineering Q4** (blocks walk): What share of the PDFs is scanned and in which languages? Finance ops answers (a plan OPEN item). A high scanned share or non-Latin text may promote the model to the 14B class, or show that OCR, not the model, is the limit.
- **ai-engineering Q5** (blocks walk, pack:regulated-corp#AI-1): Do the licences of the qwen2.5 and gemma3 weights pass legal review for this commercial use? Pack AI-1's reason is legal review of approved vendors, but its ollama/* glob approves a server prefix and not a set of weights, and each model carries its own licence. The compliance owner or the pack owner decides; a failed review changes the model, reruns the golden set and leaves the rest of this record intact.
- **architecture Q1** (blocks walk): Tenant IT answers: which Odoo version and which API does the integration use (the brief says REST, and the surface varies by version), is a non-production instance available at Walk, and can a bill be found by supplier plus supplier invoice number?
